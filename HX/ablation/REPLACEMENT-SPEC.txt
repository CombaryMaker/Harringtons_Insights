REPLACEMENT SPEC - HX Ablation Test (version 1, 8 November 2026)
Michael Hugh Harrington. The programs below are the published, well-known alternatives that the ablation app swaps in
when a user turns one of Michael's stages Off. Each must be a faithful, plain implementation of the published method:
no tuning, no extra tricks. Write from the cited description; do not copy GPL code. Public-domain or MIT code
(LZMA SDK, bitshuffle) may be followed. All numbers are little-endian. All programs: Windows x64, static, one .c file.

COMMON RULES
- Return 0 on success, non-zero with a one-line message on stderr on any error.
- Never write partial output on error (write to OUT.tmp, rename at the end).
- Must handle: empty file, 1-byte file, files up to 4 GB, sizes not divisible by any width (leftover bytes copied raw).
- Same input + same parameters = byte-identical output, on every run and every computer (no timing, no threads, no
  floating point in anything that decides the output).

========================================================================================================================
GROUP T - REVERSIBLE TRANSFORMS (Transform stage; T7 is for the Leftovers stage)
Interface:   NAME.exe f IN OUT [params]     forward
             NAME.exe i IN OUT              inverse (reads its parameters from the header)
Header of every forward output: 4-byte magic, u8 version = 1, u64 original length, then the program's own parameters.

T1 shuffle.exe     Byte shuffle (Blosc / HDF5 "shuffle" filter).       magic "SHF1"   params: u8 W (-w 2|4|8)
   Elements of W bytes; byte k of every element is written together (all byte 0s, then all byte 1s, ...).
   n mod W leftover bytes copied raw at the end. Source: HDF5 shuffle filter; Blosc (Alted).
T2 bitshuffle.exe  Bitshuffle (Masui et al. 2015).                     magic "BSH1"   params: u8 W (-w 1|2|4|8)
   Elements of W bytes, blocks of 8192 elements (last block: largest multiple of 8 elements that fits); inside a block,
   bit b of byte k of every element is gathered into one bit-plane, planes written in order (k, b). Elements left over
   (fewer than 8) and n mod W bytes copied raw. Source: github.com/kiyo-masui/bitshuffle (MIT).
T3 delta.exe       Byte delta, as the xz/7-Zip Delta filter.           magic "DLT1"   params: u16 D (-d 1..256)
   out[i] = in[i] - in[i-D] (mod 256) for i >= D; first D bytes copied. Source: XZ Utils delta filter (0BSD).
T4 bcj.exe         x86 BCJ branch converter, as xz/7-Zip "x86" filter. magic "BCJ1"   params: none
   Converts relative E8/E9 call/jump targets to absolute, exactly the LZMA SDK Bra86.c algorithm (public domain),
   start position 0. Source: LZMA SDK (Igor Pavlov).
T5 dict.exe        Dictionary encoding (Parquet PLAIN_DICTIONARY idea). magic "DIC1"  params: u8 W (-w 1|2|4)
   Values of W bytes. Dictionary = distinct values in order of first appearance (u32 K, then K values). Each value is
   written as its index in a fixed width of max(1, ceil(log2 K)) bits, packed LSB-first. If K > 65536, write flag 0 and
   copy the data raw; otherwise flag 1. n mod W leftover bytes raw. Source: Apache Parquet format specification.
T6 png.exe         PNG row filters (PNG spec section 9, libpng heuristic). magic "PNG1" params: u32 R (-r row bytes),
   u8 P (-p bytes per pixel, 1..8). Rows of R bytes (last partial row: filter 0). For each row try filters 0-4 (None,
   Sub, Up, Average, Paeth) and keep the one with the smallest sum of |signed byte| of the output (libpng's
   minimum-sum-of-absolute-differences rule); write the filter byte then the filtered row. Source: PNG spec (W3C).
T7 dedup.exe       Block deduplication with content-defined chunks (FastCDC, Xia et al., USENIX ATC 2016).
   magic "DDP1"  params: none. Gear-hash chunking, min 2 KiB, average 8 KiB, max 64 KiB, normalised chunking level 1,
   the 256-entry Gear table generated by the 64-bit xorshift* PRNG seeded with 1 (table stored in the source).
   Each chunk is either new (stored) or a duplicate of an earlier identical chunk (stored as its index). Identity by full
   byte comparison after a 64-bit hash match (no hash-only trust). Output: u32 chunk count, then per chunk
   u8 kind (0 new, 1 duplicate) + u32 length or u32 earlier chunk index, then all new chunks' bytes in order.

========================================================================================================================
GROUP G - GROUPING MAPS (Group stage). These only CLASSIFY windows; HX does the moving.
Interface:   NAME.exe IN MAP [-b WINDOW]        default WINDOW = 65536 bytes; last window may be short
MAP file:    "GMP1", u32 WINDOW, u32 COUNT, u8 K (number of classes), then COUNT bytes: class of each window (0..K-1).

G1 blocks.exe      Plain fixed blocks: every window class 0 (K = 1). The "no grouping" control.
G2 typegroup.exe   File-type grouping by content signature (7-Zip solid-archive style "group by type"). K = 4:
   0 text      at least 90% of bytes are 9, 10, 13 or 32..126, or valid UTF-8 multibyte sequences
   1 program   window contains "MZ" at offset 0 of the file (first window only) or E8/E9 opcodes are > 0.5% of bytes
   2 random    order-0 entropy of the window > 7.5 bits per byte (computed with integer counts, compared as
               sum(c*log2(n/c)) > 7.5*n using a fixed 2^16-entry log2 table in the source, no floating point)
   3 other     everything else. Rules are tested in the order 2, 0, 1, 3.
G3 histcluster.exe Byte-histogram clustering (fileprints: McDaniel & Heydari 2003; Li, Wang, Stolfo & Herzog 2005).
   K = min(4, COUNT). Each window's 256-bin histogram scaled to counts per 65536 (integer). k-means, Manhattan distance,
   initial centres = windows at indices 0, COUNT/4, COUNT/2, 3*COUNT/4, exactly 10 iterations, ties to the lower class,
   centres as integer means (floor). Classes renumbered by first appearance.

========================================================================================================================
GROUP O - ORDER MAPS (Order stage). Reorder windows inside each class; HX applies the order and stores the map.
Interface:   NAME.exe IN MAP ORDER                MAP from group G above
ORDER file:  "OMP1", u32 COUNT, then COUNT x u32: original window index for each new position. Classes stay together,
             in class order 0..K-1; inside a class, the program's order.

O1 minhash.exe     MinHash similarity chain (Broder 1997). Per window: 64 MinHash values over all 8-byte shingles,
   hash i = 64-bit FNV-1a of the shingle XOR seed_i, seeds from the same xorshift* PRNG (seed 2). Inside each class:
   start with the lowest-index window, then repeatedly append the unused window with the most equal MinHash values
   (ties: lowest index). Windows under 8 bytes count as similarity 0.
O2 histsort.exe    Byte-histogram sort. Inside each class, sort windows by key (most frequent byte value, its count
   descending, second most frequent byte value), ties by original index (stable).
(The "original order" option needs no program; HX handles it.)

========================================================================================================================
NOT FOR THE AGENT (built into HX by the other session): the Decide-stage alternatives (try every line, sample picks the
winner, entropy estimate, early abort, choice by file type), zstd --long, store raw, whole-file best-of, one-coder route,
and the back-end coders (zstd, xz, BSC, lpaq1, ZPAQ, Brotli).

TESTS EACH PROGRAM MUST PASS (record in results\)
- Round trip exact on: empty file, 1 byte, 7 bytes, 65,537 bytes of zeros, every public test file.
- Same output on two runs (compare SHA-256).
- Group/Order programs: MAP and ORDER files valid (every window appears exactly once in ORDER).

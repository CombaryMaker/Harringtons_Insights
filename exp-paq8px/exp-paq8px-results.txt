EXP-PAQ8PX - RESULTS (paq8px v217 vs the tested build "v20")
Michael Hugh Harrington, 15 November 2026

WHAT WAS TESTED
The tested build, v20, is paq8px v217 with the open-source changes described in exp-paq8px-methods.txt PLUS some
additional components that are protected and not published here. Settings: paq8px -8 (no LSTM). Every archive was
decoded and compared with the original (SHA-256): all exact. Canterbury: the 11 standard files. Silesia: the 12 full
standard files (211,938,580 bytes). Windows desktop, one file per core.

IMPORTANT - OPEN SOURCE AND PROTECTED GAINS WERE NOT SEPARATED
During testing each change was accepted one at a time on a small development set, then the finished v20 was run once
on the full corpora as a single package. By accident, the full-corpus runs did not separate the gains of the
open-source changes from those of the protected components. The full-corpus figures below are therefore for the
combined build. Section 3 gives estimated shares. The published patch on its own has not been run on the full corpora.
The Mode Context in the published patch is the always-on version (in testing it made a few files 1 to 4 bytes larger).

2. PROJECTED RESULTS WITH A "NO-WORSE" TRIGGER (not built, not measured)
A simple trigger would store a file the v217 way whenever the new build comes out larger, at a cost of about 2 bytes.
Projected: Canterbury -241 (unchanged); Silesia -13,308 (-0.046%); both corpora -13,549.

3. ESTIMATED SHARES (estimates; only the totals are measured)
Canterbury shares are measured (each change was accepted on Canterbury). Silesia shares are estimated file by file,
from which kinds of change produced each file's gain on the development set.

                                   Canterbury    Full Silesia,          Full Silesia,
                                   (measured)    no trigger (est.)      with trigger (est.)
Open-source changes (items 1-9)       -159        0 to -1,000           -4,500 to -5,400
Mode Context (item 10, CC0)            -30        -200 to -600          -200 to -600
Protected components (undisclosed)     -52        -7,700 to -8,200      -7,700 to -8,200
TOTAL                                 -241        -8,818 (measured)     -13,308 (projected)

Why the open-source share is near zero without the trigger: the open-source changes produced the large text gains
(for example dickens) but are also behind the three files that got larger (nci, webster, samba: +4,496 together);
these cancel. With the trigger the losses disappear and the open-source share shows its full size.

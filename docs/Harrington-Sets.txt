HARRINGTON SETS
Multi-core for compressors that only ever had one core.
Michael Hugh Harrington, Harrington's Insights, 29 October 2026.
Original work by Michael Hugh Harrington. Released under the MIT License (full text at the end of this document).

WHAT IT IS
Harrington Sets lets slow compressors that have always run on a single processor core use every core in the
machine. Instead of cutting a file into equal chunks, it reads the file on the spot, gathers like data from
anywhere in the file into its own streams, sets aside the parts that cannot be compressed, and gives each
stream its own model and its own core.

HOW IT WORKS
1. The file is read in 64 KB windows, and each window is measured on the spot: share of control bytes,
   letters, digits, spaces, high bytes and zeros, plus byte entropy. No format description is needed.
2. Exclusion: windows that are random or already compressed (entropy above 7.99 bits per byte) are excluded
   to a raw set that is stored as-is and never modelled.
3. The remaining windows are grouped into up to three sets of like data (k-means on the measurements).
   Runs shorter than 512 KB join their neighbour; sets under 1 MB fold into the largest set.
4. Each set's windows are joined in file order into one stream with its own model. Large streams are split
   into blocks so every core stays busy, and each block runs on its own core.
5. Layered exclusion map: map one says "set one, or excluded"; map two sorts only the excluded windows into
   set two or set three (or raw). Stored as run lengths, about 5 bytes per run, it puts every window back in
   its exact place when the file is decoded.

ORIGINALITY
Harrington Sets is an original work with loose ties to earlier ideas, all of which operate differently:
- Equal-chunk parallel blocks (pigz, pbzip2, xz -T, zstd -T, ZPAQ blocks, pcompress) cut the file blindly.
- Archivers such as FreeArc, 7-Zip and RAR group whole files by name or extension.
- OpenZL, Parquet and ORC split data into streams from a format description or schema written in advance.
- Logzip clusters lines, but only for text logs.
Harrington Sets parses on the spot, with no format knowledge, regroups like windows from anywhere in a
file into shared streams, excludes incompressible data through a layered map, and decodes the streams in
parallel inside a context-mixing compressor. To the author's knowledge no existing tool does this.
Tools that already decode in milliseconds gain little and are left as they are.

CREDITS
Harrington Sets is the method described above. The compressor it was first applied to, HCM, is close to the
work of others: its core design follows Matt Mahoney's lpaq1, with parts from paq8, lpaq and ZPAQ, the
Witten, Neal and Cleary (1987) arithmetic coder and Arm Optimized Routines. lpaq1-h is a mutant of lpaq1.
Full credits are in CREDITS.txt in this repository and in Section 1.8 of the book.

RESULTS (one run, wall clock, a 2-core machine; every file decoded back exactly)
Sizes are 1,000,000 bits down to X.
  samba (21,606,400 bytes), HCM fast
    single stream (v3.4)        157,393   compress 62.9 s   decode 16.8 s
    equal 16 MB blocks (v3.5)   159,390   compress 59.2 s   decode 13.9 s
    Harrington Sets (v3.6)      157,643   compress 42.5 s   decode  9.7 s   <- 1.73x faster decode, +0.16% size
  mozilla (51,220,480 bytes): about equal to equal blocks (261,999 vs 261,866; decode 35.4 vs 32.7 s)
  Three randomly picked medium files (2 MB blocks): 1.5x to 1.9x faster decode for 0.5% to 4.3% more size
  lpaq1-h with the same treatment: 1.6x to 1.9x faster decode
More cores give more speed; these tests had only two.

EXPECTED RANGES (estimates from the two-core results above, not yet measured)
Size increase: large mixed files about 0.1% to 1%; medium files about 0.5% to 5%; small files under about
1 MB no change, since they fold into one set and get neither size loss nor speed gain.
Speed: 2 cores 1.5x to 1.9x, which is near the two-core ceiling; 4 cores about 2.5x to 3.5x; 8 cores about
4x to 6x on large files, with medium files topping out sooner because they have too few blocks to keep
every core busy.

LOW-COST MULTI-THREADING FOR SINGLE-CORE SOFTWARE
A great deal of software is stuck on one core because it builds up state as it reads, such as an adaptive
model, a dictionary or a learned context, and that work cannot simply be handed half to another core
without breaking it. Harrington Sets gets around this cheaply. The sorting pass is a single quick read of
64 KB windows measured on seven simple features, the map costs about 5 bytes per run, and the original
program does not need to be rewritten, because each set simply gets its own copy of the same single-core
engine. The limits seen so far are that each worker learns from less data, which is the 0.16% to 4.3% size
cost measured in compression and would show up as a similar cost in other uses; that tools which are
already parallel or already fast gain little; and that the input must be large enough to give at least as
many blocks as there are cores.

USES BEYOND COMPRESSION
At its core Harrington Sets reads unknown data, sorts it by what it actually is with no format knowledge,
sets aside what is not worth working on, sends each group to its own worker in parallel, and keeps a map
that restores everything exactly. That pattern fits any slow process that learns from its input. Storage
and backup systems could skip compressed or encrypted regions instantly and send each kind of data to the
engine that suits it, saving processor time and energy at data-center scale. SSD controllers and hardware
compression chips could carry the simple fixed-cost classifier in silicon and handle mixed data without
knowing file formats. Network transfer and content delivery networks could split streams on the fly so
text, binary and media each get the right treatment while incompressible data passes straight through. AI
training pipelines could sort huge mixed datasets by content type before training or deduplication and
process each group in parallel with its own model. Scientific data such as genomics, sensor logs and
simulation output often mixes very different regions in one file, the same situation where Harrington Sets
did best on samba. Databases and log platforms could gain column-like grouping from data with no schema,
which OpenZL and Parquet can only do when the format is described in advance. Forensics already uses
entropy scanning to find encrypted or packed regions (binwalk, file carvers), so that single use is the
least new; the original contribution is the full combination of format-free sorting, the layered exclusion
map and parallel per-set models.

HOW TO USE (HCM v3.6, source hcm/hcm.cpp)
  hcm s INPUT OUTPUT     Harrington Sets, fast mode
  hcm t INPUT OUTPUT     Harrington Sets, max mode
  hcm d INPUT OUTPUT     decompress (recognises Harrington Sets files automatically)
  HCM_BLOCK_MB sets the largest block size in MB (default 16).

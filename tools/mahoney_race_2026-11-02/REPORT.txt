MATT MAHONEY TEST SETS RACE - Harrington's Insights tools vs ZPAQ 7.15 and lpaq1
Michael Hugh Harrington, 2-3 November 2026. MIT License.

WHAT WAS RACED
Matt Mahoney's own programs, built from his published source:
  ZPAQ 7.15 -m4 and -m5 (public domain), lpaq1 option 9 (GPL).
Against our tools:
  HCM v3.6.1 fast and max (single stream), HCM Sets fast and max (Harrington's Sets, all cores),
  hcmx max, zpaq-hi -m5 (ZPAQ with our per-block model search; output is a normal ZPAQ archive that
  stock zpaq extracts), lpaq1-h 9 (our lpaq1 mutant, best of six flag settings per file).
On four standard test sets:
  Calgary corpus (18 files), Canterbury large corpus (E.coli, bible.txt, world192.txt),
  Mahoney's Generic Compression Benchmark (uiq2 files from seeds 0, 1 and 2), and enwik9
  (1,000,000,000 bytes, md5 e206c3450ac99950df65bf70ef61a12d).
Every file was compressed on its own, decoded, and compared byte for byte. All 247 results are exact.

MACHINE
AMD Ryzen 5 7500X3D (6 cores, 12 threads), 16 GB RAM, Windows 11 with WSL2 (Linux 6.18, 7.5 GB
given to WSL). All programs are static Linux builds (gcc -O3 -march=x86-64-v3) run inside WSL with
the data in the Linux file system. ZPAQ was limited to 5 threads so that -m5 fits in WSL's memory;
HCM Sets used all 12 threads. Times are wall clock in seconds. HCM decodes its own output as a
check before it exits, so HCM compress time = wall time minus one decode.

WHAT STANDS OUT
1. Score: our tools take the smallest result on three of the four sets (Calgary, Canterbury large,
   Generic Compression Benchmark). Mahoney's lpaq1 takes enwik9, his home ground (large English text).
2. Decode speed on enwik9: HCM Sets max decodes the full gigabyte in 100 s, 4.2x faster than ZPAQ -m5
   (422 s) and 6.7x faster than lpaq1 (676 s), for a file 14% larger than ZPAQ -m5. HCM Sets fast
   decodes in 92 s. HCM single stream decodes in 501 s, so the speed comes from Harrington's Sets
   spreading the work over all cores.
3. zpaq-hi beats stock ZPAQ -m5 on every set (Calgary, Canterbury large, GCB, enwik9), and its archives
   are still extracted by unmodified zpaq.
4. Memory: HCM max peaks at 2.3 GB on enwik9 against 5.0 GB for ZPAQ -m5 (5 threads).

FILES IN THIS FOLDER

  summary.py         builds results_summary.txt from results.csv
  race.cmd, race.ps1 Windows launcher (keeps the PC awake, starts the WSL run)
  runt.c             timing helper: wall time, CPU time, peak memory, exit code
  results.csv        every file, every program: sizes, compress/decode times, memory, exact check
  results_summary.txt  the tables above
  progress.txt       the run log with start and finish times
  sysinfo.txt        machine details recorded by the script
Sources of the programs: ZPAQ 7.15 and lpaq1 from mattmahoney.net; HCM, hcmx, zpaq-hi and lpaq1-h
from this repository (hcm/, tools/hcmx, src/zpaq-hi, src/lpaq1-h).

HARRINGTON SETS WRAPPER (hs_wrap.py) - 30 October 2026
Michael Hugh Harrington. MIT License. Runs any single-core compressor through Harrington Sets: 64 KB windows,
entropy exclusion above 7.99 bits/byte, k-means into at most 3 sets, run smoothing, blocks of at most B MB,
one compressor copy per block on separate cores, run-length map to restore order. The compressor is unchanged.

  compress:    hs_wrap.py c IN OUT --comp "paq8px -1 {in} {out}" --decomp "paq8px -d {in} {out}" --jobs N --block-mb B
  decompress:  hs_wrap.py d IN OUT --decomp "paq8px -d {in} {out}" --jobs N
  (a command without {out} is read from standard output, e.g. --comp "xz -6 -c {in}")

VERIFICATION (2-core cloud machine, one run each, every result restored exactly)
  samba (21,606,400 bytes) with xz -6:       3,809,950 bytes, compress 5.0 s, decompress 0.2 s
  samba with HCM v3.6 fast:                  3,406,128 bytes, compress 43.8 s, decompress 10.1 s
     (HCM's own built-in sets mode gave 3,406,084 bytes: the wrapper adds 44 bytes and no time)

OBSERVATIONS
- About 1.55 times faster on 2 cores, but 10.7% larger. The 1 MB blocks were chosen only to force both cores
  to work on a small sample; each paq8px block starts with an empty model and paq8px learns slowly, so tiny
  blocks cost far more than with HCM. Real use needs much larger blocks (16 MB or more) on large files.
- This 3 MB sample formed a single set (too small for grouping), so it measured plain parallel blocks only.
- paq8px is very slow: about 5.6 KB/s per core at level -1 on this machine.

VERSION 1.1 (30 October 2026) - fixes found in an expert review of the write-up
- Windows: commands were split with POSIX rules, which strip backslashes, so Windows paths broke
  ("C:\Users\..." became "C:Users..."). Templates are now split first and {in}/{out} substituted inside
  the tokens, Windows-style on Windows. This also fixes temporary folders whose path contains a space,
  which failed on every system in 1.0.
- A failing compressor now stops the run with its own error message (1.0 hid it).
- Format HSW2 adds a CRC-32 of the original (4 bytes), checked after decoding; HSW1 files still decode.
- Blocks are started largest first, so the slowest block never starts last (better use of cores).
- Clear errors instead of assert; --comp / --decomp checked before starting.
TESTS (2-core cloud machine, every result restored exactly)

VERSION 1.2 (30 October 2026) - container validation (from a ChatGPT review point, confirmed by test)
- The decoder now checks the map, block table, raw length and total file length against each other before
  running any decoder, and reports truncated or damaged files cleanly. Format unchanged (samba with xz -6
  still 3,809,954 bytes; HSW1 files still decode).
- Damaged-file test (corrupt_test.py, 8 cases on a 3 MB file): 1.1 printed a raw Python error on one case and
  hung for over 120 s on a file with a forged run count; 1.2 gave a clean error on all 8.
- Boundary test (make_edge.py + edge_test.sh, 16 files: 0 and 1 byte, 4095/4096, 65,535/65,536/65,537,
  1 MiB -1/0/+1, 2 MiB+1, 3 MiB, 16 MiB+1, all-zero and random): 16 wrapper round trips with xz, all exact,
  with 1.1 and again with 1.2.

HCM v3.6 "sets" mode (29 October 2026) - Michael Harrington's exclusion idea. Source: hcm/hcm.cpp.
Commands: s = fast, t = max. Decompress (d) recognises the "HCMS" format automatically.

HOW IT WORKS
The file is read in 64 KB windows. Windows that are random or already compressed (byte entropy above
7.99 bits per byte) are excluded to a raw set and stored, never modelled. The remaining windows are
grouped into up to 3 sets by their byte statistics (control, letters, digits, spaces, high bytes, zeros,
entropy; k-means). Runs shorter than 8 windows (512 KB) take the label of the run before them, and
sets under 1 MB are folded into the largest set. Each set's windows are joined in file order and
compressed with their own HCM model; large sets are split into 16 MB blocks; every block runs on its
own processor core. A run-length map of the labels (5 bytes per run) puts every window back.

OBSERVATIONS
- samba: a clear win over parallel blocks on both size and speed, and close to single-stream size.
- mozilla: about the same as plain parallel blocks (0.05% larger, 8% slower decode). Its largest set
  is 43 MB of code, cut into three blocks, and with only 2 cores the 5 blocks decode in 3 rounds, so the
  slowest round sets the time. On 4+ cores this would improve.
- The first try's raw rule (7.95 bits/byte) excluded 1.9 MB that HCM could still shrink a little, and
  without smoothing mozilla split into 257 runs; both hurt. Tuned settings fixed both.
- Not yet tried: warming each set's model with a shared sample, more than 3 sets, choosing sets by
  trial compression instead of byte statistics.

RANDOM 5-FILE TEST (29 Oct 2026; seed 1793303107 picked from Canterbury + Silesia files up to 11 MB;
2 MB blocks so medium files use both cores; 2-core machine; all decoded exactly). See random5_results.txt.
- Medium files (6-10 MB): decoding 1.5x to 1.9x faster and compression 1.6x to 1.9x faster, for 0.5%
  to 4.3% more size. Plain blocks were slightly smaller than sets on these single-type files; sets were
  slightly faster (x-ray 4.5 s vs 5.0 s, reymont 2.8 s vs 3.3 s decode).
- Small files (alice29.txt, ptt5): one block, no speed-up; sets mode adds about 30 bytes of map.
- Smaller blocks cost more size: 2 MB blocks lose more than 16 MB blocks because each block starts empty.

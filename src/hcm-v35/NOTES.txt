HCM v3.5 (29 October 2026) - source is hcm/hcm.cpp in this repository.

WHAT IS NEW
1. Parallel blocks. Commands p (fast) and q (max) cut a large file into blocks (16 MB by default,
   set HCM_BLOCK_MB to change it) and compress and decompress the blocks on separate processor
   cores. The file starts with "HCMP". Decompression (command d) recognises it automatically.
2. Sections. The file is read in 64 KB windows and each is marked text or binary (same test as the
   whole-file check); stretches under 256 KB are merged into their neighbours. If a file really mixes
   both, one extra pass is made in which a single model runs through the whole file and only the
   text/binary contexts switch at each boundary (nothing is reset). It is kept only if smaller.
   Mode-byte bit 6; the section table follows the header. Every older .hcm file decodes as before.

RESULTS (Silesia, fast mode, one run, wall clock, 2-core cloud machine, all decoded exactly)
  samba   (21,606,400)  v3.4 3,400,668 B  compress 62.9 s  decode 16.8 s
                        v3.5 3,400,668 B  compress 76.6 s  decode 17.5 s   (sections did not help)
                        v3.5 parallel 16 MB 3,443,819 B  compress 59.2 s  decode 13.9 s
  mozilla (51,220,480)  v3.4 13,355,236 B compress 180.8 s decode 47.0 s
                        v3.5 13,351,973 B compress 224.7 s decode 50.0 s   (sections: -3,263 bytes)
                        v3.5 parallel 16 MB 13,412,925 B compress 130.2 s  decode 32.7 s
  Compression ratio: samba 6.354 (v3.4) / 6.274 (parallel); mozilla 3.835 (v3.4) / 3.819 (parallel).
  1,000,000 bits down to: samba 157,393 -> 159,390 parallel; mozilla 260,739 -> 261,866 parallel.

OBSERVATIONS
- Sections are a failure as built: samba gained nothing and mozilla 0.02%. HCM's binary mode mainly
  adds record contexts, and the binary parts of these archives are not fixed-length records, so
  switching contexts by section changes little. The extra pass costs about 20% more compression time.
- Parallel blocks work: on only 2 cores decoding was 1.21x faster on samba (+1.3% size) and 1.44x
  faster on mozilla (+0.4% size). The speed-up grows with the number of cores (about one block per
  core); on an 8-core PC mozilla's 4 blocks would all decode at once.
- Silesia files under 16 MB are unchanged in parallel mode (one block).

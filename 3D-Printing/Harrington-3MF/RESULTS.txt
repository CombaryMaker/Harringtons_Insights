Test: 20 real STL files exactly as published (Voron-2, Original Prusa i3, NASA 3D Resources, 3DBenchy).
Each file was turned into 3MF by: lib3mf 2.5.0 (3MF Consortium reference library), trimesh 5.2.1, and Harrington-3MF
(the research encoder in this folder, the same code as Harrington-3MF.exe, built for Linux for the test). Sizes in bytes.
"STL zip" = the STL file in a zip at deflate level 9. "smaller" = Harrington-3MF compared with the smaller of lib3mf and trimesh.
Exactness: every Harrington-3MF file was unpacked and every number read back: all 20 exact (same triangles, bit-exact
float32 coordinates). They were also read with lib3mf and trimesh (earlier concept test): exact. lib3mf-written files
were not exact on any file (lib3mf rounds coordinates when writing). trimesh-written files were exact.
Encode time = whole program run, one thread, cloud VM (Intel Xeon 2.1 GHz). The 3MF standard forbids triangles that
repeat a corner; all writers leave them out (3DBenchy has 550, Hubble "All pieces" 8).

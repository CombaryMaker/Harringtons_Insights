The benchmark below (14 November 2026) measured the STL-Harrington mesh coder against the other exact mesh coders and plain
packers, all in one test program under the same rules. STL-Harrington.exe uses the same coder; a .stlh file adds a 16-byte
header and, for binary STL, the original 80-byte STL header (packed with the rest), so its files are a few dozen bytes larger
than the coder sizes below. Example: nasa_01_side_a 7,257 bytes in the benchmark (zstd), 7,306 as a .stlh file (Fast).
"Smallest" in the program = the ZPAQ -m5 rows; "Fast" = the zstd -19 rows. The benchmark program (meshbench2.cpp) is in
source/benchmark/.

STL-HARRINGTON - FAIR SPEED AND SIZE BENCHMARK (C++), 14 November 2026. Michael Hugh Harrington research, MIT License.
STL-Harrington = the stlx3 coder (working name) ported to C++. All coders run in one program (meshbench2.cpp), same rules:
  - every coder starts from the same indexed mesh in memory (float32 positions + triangle list) and ends with it decoded;
    reading/writing files is not timed (in-memory, like TurboBench). One thread. Median of 5 runs (3 for files over 20 MB;
    ZPAQ: 3, or 1 over 20 MB).
  - every decoded result checked: same triangles, bit-exact float32 coordinates, winding kept (triangle order/rotation free).
    "raw STL" rows are checked byte for byte against the original file.
  - STL-Harrington encode time includes trying 3 triangle orders (file order, neighbour pre-sort, side walk) and keeping
    the smallest (zstd -3 used to choose), then the final back end. meshoptimizer: vertex-cache + vertex-fetch order,
    lossless index/vertex codecs (vertex level 2). Draco 1.5.9 Edgebreaker speed 0 (=-cl 10), no quantization.
Machine: cloud VM, Intel Xeon @ 2.10 GHz, 2 vCPUs (1 used), Ubuntu 24.04, g++ 13.3 -O3 -march=x86-64-v2.
Libraries: zstd 1.5.6, liblzma 5.4.5, libzpaq 7.15, meshoptimizer 1.3, OpenCTM 1.0.3 (MG1, level 9), Draco 1.5.9.
Data: 21 real STL files exactly as published (Voron-2, Original Prusa i3, NASA 3D Resources, 3DBenchy, a gyroid) and 6 scan
models converted to STL by us (fandisk, rocker arm, Stanford bunny, Happy Buddha, armadillo, Nefertiti). 198,064,268 bytes.
Units: bytes; ratio = STL bytes / compressed bytes; bpt = bits per triangle; bpv = bits per vertex; MB/s = STL bytes per
second (10^6); Mtri/s = million triangles per second; memory = peak resident memory of the whole process (includes the
loaded STL file and the indexed mesh).

4. NOTES
  - Draco was NOT exact on 2 files (Hubble all pieces, 3DBenchy): it drops zero-area triangles.
  - STL-Harrington keeps exact geometry, not the STL file bytes (header and stored normals are not kept); so do meshoptimizer,
    OpenCTM and Draco. An earlier Python version (stlx) kept the STL bytes exactly; it is not part of this release.
  - meshoptimizer decodes far faster than anything else here (about 2.5 GB/s with zstd); STL-Harrington with zstd decodes at
    about OpenCTM speed. Speed figures are from a 2-vCPU cloud VM; relative order is what matters.
  - The neighbour pre-sort uses meshoptimizer's vertex-cache sort (MIT) - credited.
